## Система команд
**Розташування:** `src/logic/systems/commands/`
**Призначення:** Управління виконанням команд для об'єктів у грі, включаючи черги команд, групи команд та динамічну резолюцію параметрів.

### Підпапки / Файли
- `command.types.ts` — основні типи та інтерфейси для команд
- `CommandSystem.ts` — головна система управління командами
- `CommandQueue.ts` — черга команд для одного об'єкта
- `CommandExecutor.ts` — абстрактний базовий клас для виконавців команд
- `CommandGroupSystem.ts` — система управління групами команд і планами
- `command-group.types.ts` — типи для груп команд
- `CommandScheduler.ts` — планувальник виконання планів/команд
- `CommandContextStore.ts` — сховище контексту та кешів резолюції параметрів
- `ParameterResolutionService.ts` — сервіс резолюції параметрів
- `ParameterResolvers.ts` — резолвери для різних типів параметрів
- `ValidationService.ts` — сервіс валідації параметрів
- `AutoGroupMonitor.ts` — моніторинг автоматичних груп команд
- `executors/` — конкретні виконавці команд (MoveToExecutor, CollectResourceExecutor, тощо)
- `db/` — база даних команд та груп команд
- `plans/` — типи вузлів плану, інстанси та фабрики команд для декларативних груп

### Залежності
- Використовує: `@interfaces/index`, `@core/game/GameContainer`, `@systems/save-load`
- Використовується у: `src/logic/core/game/GameServices.ts`, UI компонентах для відправки команд

### Основні компоненти

#### CommandSystem
Центральна система управління командами:
- Керує чергами команд для кожного об'єкта
- Створює та управляє виконавцями команд (executors)
- Працює в парі з `CommandScheduler`, повідомляючи про завершення/помилки команд
- Інтегрується з системою збереження/завантаження

#### CommandQueue
Черга команд для одного об'єкта:
- Послідовне виконання команд
- Підтримка пріоритетів команд
- Вставка команд в середину черги
- Управління поточним індексом команди

#### CommandExecutor
Базовий клас для виконавців команд:
- Абстрактні методи: `canExecute()`, `execute()`, `completeCheck()`
- Управління енергією та power споживанням
- Утилітні методи для ротації об'єктів
- Інтеграція з контекстом команди

#### CommandScheduler
Відповідає за рантайм планів команд:
- Тримає черги активних `PlanInstance` на об'єкт
- Здійснює диспетчеризацію наступної команди та відслідковує pending-команди
- Обробляє перезапуски плану за кодами помилок та викликає колбеки системи

#### CommandContextStore
Сховище контексту й кешів резольвера:
- Реєструє контекст для кожного плану та пов'язаного пайплайну резолюції
- Викликає `ParameterResolutionService` у потрібні моменти (`group-start` / `before-command`)
- Надає доступ до розв'язаних значень через `getResolvedValue`

#### CommandGroupSystem
Система управління групами команд:
- Створення `PlanInstance` за декларативним описом групи
- Реєстрація планів у `CommandScheduler` та відслідковування станів груп
- Інтеграція з системою вимог (requirements) та збереження/завантаження стану

### Типи команд
- `move-to` — переміщення до позиції
- `collect-resource` — збір ресурсів
- `unload-resources` — розвантаження ресурсів
- `load-resources` — завантаження ресурсів
- `build` — будівництво
- `build-road` — будівництво сегментів доріг
- `charge` — зарядка
- `wait` — очікування
- `attack` — атака

### Особливості системи
- **Динамічна резолюція параметрів**: Параметри команд можуть розв'язуватися динамічно через пайплайни
- **Групи команд**: Команди описуються декларативними планами та можуть містити вкладені цикли/умови
- **Перезапуски планів**: Планувальник може повторно запускати план з початкового стану за кодами помилок
- **Деревоподібні плани**: Планувальник виконує композицію вузлів `PlanNode` (sequence/loop/condition/action)
- **Система пріоритетів**: Команди можуть мати різні пріоритети
- **Управління енергією**: Автоматичне споживання power під час виконання команд
- **Збереження стану**: Повна підтримка збереження/завантаження стану команд
