## Системи
**Розташування:** `src/logic/systems/`
**Призначення:** Системна логіка та інфраструктура гри. Системи відповідають за функціональність, що не прив'язана до конкретних доменних об'єктів.

### Підпапки / Файли

#### commands/
- `CommandSystem.ts` — головна система управління командами
- `CommandQueue.ts` — черга команд для одного об'єкта
- `CommandExecutor.ts` — базовий клас виконавця команд
- `CommandGroupSystem.ts` — система управління групами команд
- `command.types.ts` — типи для команд
- `command-group.types.ts` — типи для груп команд
- `ParameterResolutionService.ts` — сервіс резолюції параметрів
- `ParameterResolvers.ts` — резолвери для різних типів параметрів
- `ValidationService.ts` — сервіс валідації параметрів
- `AutoGroupMonitor.ts` — моніторинг автоматичних груп команд
- `executors/` — конкретні виконавці команд
- `db/` — база даних команд та груп команд

#### map/
- `map-logic.ts` — головна логіка карти та генерації ресурсів
- `map-config.ts` — конфігурація карти
- `map-generation-state.ts` — стан генерації карти
- `map-init.ts` — ініціалізація карти
- `seeded-random.ts` — детермінований генератор випадкових чисел
- `index.ts` — експорт модуля

#### modifiers-system/
- `BonusSystem.ts` — головна система бонусів та модифікаторів
- `BonusRegistry.ts` — реєстр джерел бонусів
- `DependencyGraph.ts` — граф залежностей для бонусів
- `FormulaEngine.ts` — движок формул для розрахунків
- `bonus-system.types.ts` — типи для системи бонусів
- `README.md` — документація системи
- `index.ts` — експорт модуля

#### requirements/
- `RequirementsSystem.ts` — система перевірки вимог
- `requirements.types.ts` — типи для вимог
- `index.ts` — експорт модуля

#### save-load/
- `save-manager.ts` — менеджер збереження/завантаження
- `save-load.types.ts` — типи для збереження/завантаження
- `index.ts` — експорт модуля

#### scene/
- `scene-logic.ts` — головна логіка 3D сцени
- `scene.types.ts` — типи для сцени
- `dynamics-logic.ts` — логіка динамічних об'єктів
- `terrain-manager.ts` — управління террейном
- `path-finding/` — система пошуку шляхів
- `selection/` — логіка вибору об'єктів

#### environment/
- `EnvironmentLogic.ts` — керування погодою, часом доби та атмосферними ефектами
- `environment.types.ts` — типи конфігурацій та даних ефектів
- `index.ts` — експорт системи

#### camera/
- Система управління камерою (деталі в окремій документації)

### Залежності
- Використовує: `@interfaces/index`, `@core/game/GameContainer`, `@modules/*`
- Використовується у: `src/logic/core/game/GameServices.ts`, UI компонентах

### Основні компоненти

#### CommandSystem (детально описано в commands-system.md)
Система управління командами:
- Черги команд для об'єктів
- Виконавці команд
- Групи команд з динамічною резолюцією параметрів
- Циклічні групи команд

#### MapLogic
Головна логіка карти та генерації ресурсів:
- Генерація ресурсів на карті
- Управління зібраними ресурсами
- Система кластерів для розміщення ресурсів
- Детермінована генерація через seeded random
- Автоматична генерація хмар

#### BonusSystem
Система бонусів та модифікаторів:
- Реєстр джерел бонусів
- Граф залежностей між бонусами
- Движок формул для розрахунків
- Кешування результатів для продуктивності
- Автоматичне оновлення залежних значень

#### RequirementsSystem
Система перевірки вимог:
- Перевірка реквайрментів для апгрейдів
- Перевірка реквайрментів для будівель
- Перевірка реквайрментів для ресурсів
- Детальна інформація про стан вимог

#### SceneLogic
Головна логіка 3D сцени:
- Управління об'єктами сцени
- Система сітки для швидкого пошуку
- Dirty flags для оптимізації рендерингу
- Синхронізація ротації з террейном
- Система тегів для фільтрації об'єктів

#### EnvironmentLogic
Система середовища та атмосфери:
- Добовий цикл і розрахунок положення сонця
- Динамічна погода (температура, вітер, хмарність)
- Процедурне породження пилових та небесних хмар
- Керування полярними сяйвами та іншими ефектами
- Підготовка даних для рендеру освітлення та шейдерів неба

#### SaveLoadManager
Система збереження/завантаження:
- Централізоване збереження стану всіх систем
- Типізовані дані для збереження
- Відновлення стану після завантаження

### Особливості систем
- **Модульність**: Кожна система має чітко визначену відповідальність
- **Інтеграція**: Системи інтегруються через інтерфейси та GameContainer
- **Продуктивність**: Використання кешування та dirty flags для оптимізації
- **Типізація**: Повна типізація всіх системних компонентів
- **Розширюваність**: Легке додавання нових систем через інтерфейси
